# We3 System Architecture

## Overview

We3 is structured around a decoupled **Goal -> Proposal -> Run Engine -> State Mutation** lifecycle[cite: 2].

┌─────────────────┐      ┌──────────────────────────┐      ┌─────────────────────────┐
│ Customer Input  │ ───> │  Orchestrator Engine     │ ───> │  Proposal Staging       │
└─────────────────┘      └──────────────────────────┘      └─────────────────────────┘
│
┌─────────────────┐      ┌──────────────────────────┐                   ▼
│ State Mutation  │ <─── │  Autonomy Run Engine     │ <─── [ Human Approval Gate ]
└─────────────────┘      └──────────────────────────┘


## Core Modules

### 1. Goals & Proposals (`src/features/goals/` & `src/features/orchestrator/`)
* **`GoalHome.tsx`**: Accepts high-level user intentions[cite: 2].
* **`PlanPreview.tsx`**: Displays the decomposed sub-tasks generated by the primary LLM before execution[cite: 2].
* **`ProposalCard.tsx`**: Renders structured proposals inside the floating `OrchestratorDock` for human sign-off[cite: 2].

### 2. Autonomy Run Engine (`src/lib/autonomy/`)
* **`coordinator.ts`**: Evaluates task dependencies and orchestrates parallel agent execution loops[cite: 2].
* **`executor.ts`**: Invokes specific tool calls or model prompts for a given task step[cite: 2].
* **`eligibility.ts`**: Pure functions determining whether a card is ready for agent processing based on column state and prerequisites[cite: 2].
* **`feedForward.ts`**: Takes structured JSON output from a completed card and injects it into downstream card parameters[cite: 2].

### 3. Data & Repository Layer (`src/lib/repository/`)
* **`firestoreRepository.ts`**: Handles async persistence to Firebase Firestore for production multi-device sync[cite: 2].
* **`memoryRepository.ts`**: In-memory repository providing instant state mutations for offline testing and offline-first performance[cite: 2].
